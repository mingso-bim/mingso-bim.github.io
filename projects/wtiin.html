IMPLEMENTATION

Chaos의 물리 파편을 직접 제어해 역행을 구현

Geometry Collection에 External Cluster Strain을 적용해 파괴한 뒤, 타격 위치를 중심으로 URadialVector를 적용해 파편을 비산시켰습니다. 타격 위치가 오브젝트 중심에서 벗어나 있으므로 파편은 결과적으로 공격 반대 방향을 중심으로 퍼지게 됩니다.

복원 시에는 파괴 후 Fragment의 Transform을 시작점으로 사용하고, 파괴 전에 저장한 Transform을 목표점으로 설정해 위치와 회전을 보간했습니다.

TECHNICAL DECISION

Cache 역재생 대신 Runtime 제어 방식 선택

초기에는 파괴 장면을 Cache로 기록해 역재생하는 방식도 검토했습니다. 모바일 환경에서의 메모리 부담과 프로젝트 요구사항을 고려해 Chaos 물리 상태를 직접 제어하는 방식으로 변경했습니다.

PROBLEM SOLVING · MULTIPLAYER

Fragment 단위 충돌 판정의 네트워크 비용 개선

각 Fragment의 Transform을 지속적으로 동기화하면서 파편 수에 비례해 패킷량이 증가하는 것을 네트워크 프로파일링으로 확인했습니다.

→
After 물리 연출과 서버 피해 판정을 분리

Chaos Fragment의 물리 움직임과 서버 피해 판정을 분리했습니다. Fragment의 개별 위치를 서버 판정에 사용하지 않고, 마지막 공격자의 반대 방향에 Box 형태의 DamageVolume을 배치한 뒤 서버에서 Overlap 대상과 팀을 확인해 피해를 적용했습니다.

구조에 따른 계산값 · 실제 측정값 아님

맵에 배치된 20~30개의 BA가 각각 12개의 Fragment로 구성되어 있어, 모든 BA가 동기화 대상인 최악의 조건에서는 프레임마다 최대 240~360개의 Fragment Transform을 갱신해야 하는 구조였습니다.

  • BA20~30개
  • BA당 Fragment12개
  • 최악의 조건240~360회/프레임
  • 30FPS 기준7,200~10,800회/초
  • 60FPS 기준14,400~21,600회/초

위 수치는 Fragment Transform 갱신 단위의 이론값이며, 측정한 패킷 수나 바이트 수가 아닙니다.

DamageVolume 생성 및 시각적 확인

BA 내부에서 Runtime에 생성하는 UBoxComponent로, 각 실행 환경에서 생성·확인이 가능합니다.

실제 피해 적용

Overlap 결과를 이용한 피해 적용은 HasAuthority()를 확인한 서버에서 수행합니다.

개별 Fragment의 위치를 서버에서 지속적으로 추적하는 대신, 게임플레이에 필요한 비산 방향을 LastAttacker 기준으로 계산하고 해당 영역에 포함된 플레이어에게 일회성 피해를 적용했습니다. Chaos 파편의 실제 비산은 타격 위치 중심의 Radial Vector가 만들고, 공격자의 위치는 DamageVolume의 배치 방향을 정하는 데 사용합니다.

DEBUGGING

Timer Callback과 객체 생명주기 문제 대응

문제
레벨 전환을 지연시키는 Timer Callback이 GameMode의 수명 이후 실행될 가능성으로 인해 크래시 발생
원인
Timer 실행 시점과 Callback에서 참조하는 UObject의 생명주기 불일치
해결
기존 TimerHandle을 정리하고 GameMode를 TWeakObjectPtr로 캡처한 뒤, Callback 실행 시 유효성을 확인하도록 변경

기존 Timer를 정리하는 처리와 약한 참조를 통한 객체 유효성 검사를 함께 적용해, 지연 실행 시점에 GameMode가 유효할 때만 레벨을 전환하도록 했습니다.

코드 보기

실제 코드 일부 발췌 · WTTutorialGamemode.cpp — OpenMainMenu() 

void AWTTutorialGamemode::OpenMainMenu()
{
    // 1) 이미 타이머가 돌고 있다면 취소
    GetWorldTimerManager().ClearTimer(MainMenuTimerHandle);
    // 2) 약한 참조 캡처
    TWeakObjectPtr<AWTTutorialGamemode> WeakThis(this);
    // 3) 5초 뒤에 실제 레벨 전환
    GetWorldTimerManager().SetTimer(
        MainMenuTimerHandle,
        FTimerDelegate::CreateLambda([WeakThis]()
            {
                if (!WeakThis.IsValid()) return;
                // 안전하게 레벨 전환
                UGameplayStatics::OpenLevel(WeakThis.Get(), FName(TEXT("MainMenuLevel")), true);
            }),
        5.0f,
        false
    );
}

각 이벤트 핸들러는 현재 상태를 확인한 뒤 다음 상태로 전환합니다. Breakable Actor 파괴 이벤트는 AttackBA에서 AttackNPC로, 복원 이벤트는 UseSkill에서 End로 전환합니다.

코드 보기

실제 코드 일부 발췌 · WTProjectileDescent.cpp — Tick() (원본 주석 생략) 

void AWTProjectileDescent::Tick(float DeltaTime)
{
    Super::Tick(DeltaTime);

    AccumulatedDistance += ProjectileSpeed * DeltaTime;

    float u = AccumulatedDistance / 800.0f;
    u = FMath::Clamp(u, 0.0f, 1.0f);

    FVector LinearOffset = InitialForwardVector * AccumulatedDistance;
    FVector SideDirection = FVector(-InitialForwardVector.Y, InitialForwardVector.X, 0.f).GetSafeNormal();

    float LateralFactor = FMath::Sin(2 * PI * u);
    FVector LateralOffset = SideDirection * (CurveAmplitude * LateralFactor);

    FVector NewLocation = InitialLocation + LinearOffset + LateralOffset;
    SetActorLocation(NewLocation, true);

    CheckMovedDistance();
}
